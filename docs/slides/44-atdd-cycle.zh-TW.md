# ATDD 循環
### 在寫程式*之前*就對驗收測試達成共識

軟體測試視覺化系列 #44 · 驗收與 E2E
搭配工具：`/section-acceptance`（[ATDDCycleExplorer](../../src/components/ATDDCycleExplorer.js)）

<!-- ATDD 是包在 BDD（#38）外面的流程。本講重點：驗收測試是事先做出的「共同協議」，不是最後做的檢查。 -->

---

## 為什麼有這一講

- BDD（#38）給了我們驗收測試的*記法*。ATDD 給我們建立它們的*流程*。
- 慣常的順序 —— 先建、再測 —— 會**很晚**才發現誤解（#14 的成本曲線）。
- **ATDD**（驗收測試驅動開發）把它翻過來：團隊**先**對驗收測試達成共識，那個測試*定義了「完成」*。
- 驗收測試成了一份在任何程式碼之前就寫好的契約。

---

## 四階段循環：四個 D

ATDD 讓每個故事走過四個階段：

```
   Discuss ──▶ Distill ──▶ Develop ──▶ Demo
   討論       提煉        開發        展示
      ▲                                  │
      └──────────────────────────────────┘
```

| 階段 | 發生什麼 |
| --- | --- |
| **Discuss 討論** | 團隊用具體範例探索故事 |
| **Distill 提煉** | 範例被提煉成明確的驗收測試 |
| **Develop 開發** | 寫程式碼讓那些測試通過 |
| **Demo 展示** | 對著真實的故事展示通過的測試 |

---

## Discuss 討論 —— 先建立共同理解

故事*以團隊為單位*被探索 —— 通常是 **Three Amigos**（業務、開發、測試；見 #M5）：

- 具體範例讓散文藏起的邊界案例浮現。
- 待解問題*現在*就被提出，趁它只值一小時、而非一個 sprint 的時候（#14）。
- 產出是一份共同理解 —— 還不是測試，但是測試的原料。

討論是廉價地殺死含糊之處的地方。

---

## Distill 提煉 —— 範例變成驗收測試

來自*討論*的範例被**提煉**成明確、可檢查的驗收測試：

- 以業務可讀的形式寫成 —— Gherkin（#38）是常見記法。
- 每個測試指明一個前置條件、一個動作、一個預期結果。
- 這組測試現在**定義了「完成」**：故事在、且僅在它們通過時才算完成。

> 提煉把「我們談過了」變成「這是我們協議好的測試」。

---

## Develop 與 Demo —— 朝著一個已知目標建構

**Develop 開發** —— 團隊寫程式碼讓提煉出的測試通過。
- 目標固定且明確；sprint 中途沒有「他們是什麼意思？」。
- 驗收測試持續執行，作為完成定義的檢查。

**Demo 展示** —— 對著原始故事展示通過的測試。
- 展示*就是*驗收：利害關係人看到協議好的測試通過。
- 任何未被某個提煉測試涵蓋的東西，依定義就不在範圍內。

---

## ATDD vs TDD

兩者都是「測試先行」—— 在不同的高度：

| | TDD | ATDD |
| --- | --- | --- |
| 層級 | 單元 | 驗收／故事 |
| 對象 | 一個開發者 | 整個團隊 |
| 測試問 | 「這個函式能運作嗎？」 | 「我們建了對的功能嗎？」 |
| 由誰寫 | 開發者 | Three Amigos 一起 |

TDD 驅動*程式碼*；ATDD 驅動*功能*。它們巢狀 —— 一個 ATDD 故事內含許多 TDD 迴圈。

## 工具演示

在 `/section-acceptance` 開啟 **ATDD 循環探索器**：

1. 逐步走過 **Discuss → Distill → Develop → Demo**。
2. 在 *Discuss* 看範例被蒐集；在 *Distill* 看它們變成驗收測試。
3. 注意 *Develop* 瞄準的是一組固定、事先協議好的測試。
4. 看 *Demo* 對著原始故事閉合迴圈。

## 小結

- **ATDD** 在程式碼**之前**就對驗收測試達成共識 —— 測試定義「完成」。
- 循環是四個 D：**Discuss → Distill → Develop → Demo**。
- *Discuss* 及早殺死含糊；*Distill* 把範例變成可檢查的測試；*Develop* 朝固定目標建構；*Demo* 就是驗收。
- ATDD 驅動**功能**；TDD 驅動**程式碼** —— 兩者巢狀。

**課堂練習：** 拿一個你熟悉的故事。列出兩個你會在 *Discuss* 提出的範例，再把一個提煉成 Given/When/Then 測試。
