# 等價突變體問題
### 那個*殺不死*的突變體

軟體測試視覺化系列 #32 · 進階測試
搭配工具：`/section-advanced`（[EquivalentMutantExplorer](../../src/components/EquivalentMutantExplorer.js)）

<!-- 進階測試系列的第一講。它鋪陳突變測試的核心麻煩，#33 接著繞著它做度量。 -->

---

## 為什麼有這一講

- 突變測試在程式中植入小錯誤（**突變體**），並問：測試套件能**殺死**它們嗎？
- 但有些突變體在**行為上與原程式完全相同** —— *沒有任何輸入*能產生不同輸出。
- 這些**等價突變體**永遠殺不死 —— 卻會拖低突變分數。
- 偵測它們在一般情況下不可判定；這一講展示一個實用、LLM 輔助的做法。

---

## 什麼是等價突變體？

一個突變體是**等價的**，若它對**每一個**輸入都算出與原程式*相同的函式*：

```js
// 原始
for (i = 0; i < n; i++) { … }

// 突變體 —— '<' 改成 '!='
for (i = 0; i != n; i++) { … }
```

若 `i` 只會從 `0` 遞增，`i < n` 與 `i != n` 就是**等價的** —— 迴圈行為完全相同。沒有測試能分辨它們。

---

## 等價突變體為何有害

突變分數是 `殺死數 / 非等價總數`（見 #33）。若等價突變體被*誤算成存活*：

- 分數會**人為地偏低** —— 套件看起來比實際差。
- 工程師去追那些**不可能**被涵蓋的「未涵蓋」突變體。
- 時間浪費在替不存在的行為寫測試。

> 一個等價突變體存活，*不是*測試缺口 —— 它是一個*非錯誤*。

把這兩者分開，就是等價突變體問題。

---

## 為什麼它很難

判定兩個程式是否算出相同的函式是**不可判定的** —— 等價於停機問題。

- 一般而言，你無法自動*證明*等價。
- 歷史上，這是突變測試最大的人工成本。
- 實用的答案：別追求一個判定程序 —— 追求一個**夠好的分類器**，便宜地處理常見案例、其餘標記出來。

---

## 一個三步分類器

ACH 做法（Meta，arXiv 2501.12862）依成本遞增的順序篩突變體：

| 步驟 | 檢查 | 抓到 |
| --- | --- | --- |
| 1. 語法 | 突變體與原程式文字上完全相同？ | 瑣碎的無操作 |
| 2. 去註解／格式 | 正規化空白與註解後相同？ | 純表面的突變 |
| 3. LLM 裁判 | 問 LLM：*這兩段在行為上等價嗎？* | 語意上的等價 |

便宜的決定性檢查先做；昂貴的 LLM 判斷只用在存活下來的部分。

---

## LLM 裁判 —— 優點與限制

第 3 步用 LLM 當*語意*等價裁判：

**為何有幫助** —— LLM 能推理意圖與常見慣用法（單調迴圈下的 `i<n` vs `i!=n`），那是語法檢查抓不到的。

**它的限制** —— LLM 的判決是*啟發法*，不是證明。它兩個方向都可能出錯。所以：
- 「等價」的判決是一個**強烈提示**，仍需審查。
- 分類器*減少*人工心力；它不消除人。

---

## 小結

- **等價突變體**算出與原程式相同的函式 —— *沒有測試能殺死它*。
- 被算成存活時，它讓突變分數**人為偏低**並浪費心力。
- 偵測等價是**不可判定的** —— 追求分類器，而非證明。
- 一條由便宜到昂貴的管線（語法 → 正規化 → **LLM 裁判**）處理大多數案例；判決是提示、非證明。

**課堂練習：** `x = x + 0` 一定是等價突變嗎？`a && b` → `b && a` 呢？各自說明理由。
