# 探索式測試（Exploratory Testing）
### 不是「亂點」—— 是一項有紀律的技能

軟體測試視覺化系列 #26
搭配工具：`/section-blackbox`（[ExploratoryTestingExplorer](../../src/components/ExploratoryTestingExplorer.js)）

## 為什麼有這一講

- 腳本式技術（#19–#24）在執行*之前*就設計好每一個測試。
- 但腳本只能找到它的作者已經想像過的東西。
- 探索式測試**交織**學習、測試設計與執行 —— 每個測試都告知下一個。
- 要打破的誤解：探索式 ≠ 沒有結構。它是*有紀律的*，只是不是*事先腳本化的*。

---

## 定義

> **探索式測試**是同時進行的**學習**、測試**設計**與測試**執行**（Cem Kaner）。

```
   學習 ──▶ 設計 ──▶ 執行
     ▲                  │
     └──────────────────┘
        每個結果餵養下一個
```

測試者本身就是測試生成引擎 —— 持續調適，而非照清單走。

---

## 章程（Charter）給它結構

一次探索式 session 由一份**章程**界定 —— 一句簡短的任務宣言：

> *「探索**折扣碼功能**，使用**無效與過期的折扣碼**，以發現**它如何處理不良輸入**。」*

一份章程指明：探索**什麼** · 用**哪些資源** · 以發現**什麼資訊**。有時間盒（例如 60–90 分鐘）。章程就是那個結構 —— 它裡面的步驟不是事先寫好的。

---

## SFDIPOT —— 探索的覆蓋模型

要*徹底*探索，就走一遍產品的模型。James Bach 的 **SFDIPOT**：

| | 維度 | 問… |
| --- | --- | --- |
| **S** | 結構 Structure | 產品是由*什麼構成* |
| **F** | 功能 Function | 它*做什麼* |
| **D** | 資料 Data | 它*處理什麼* |
| **I** | 介面 Interfaces | 它如何被*操作*／連接 |
| **P** | 平台 Platform | 它*依賴什麼* |
| **O** | 運作 Operations | 它在現場將*如何被使用* |
| **T** | 時間 Time | *時序／順序*如何影響它 |

SFDIPOT 把「探索這個產品」化為七個具體的角度。

---

## 啟發法 —— 測試者的工具箱

啟發法是可重用的提示，建議*下一步試什麼*。一組經典的是 **HICCUPPS** —— 產品是否與它的歷史（**H**istory）、形象（**I**mage）、可比產品（**C**omparable）、宣稱（**C**laims）、使用者期望（**U**ser）、產品本身（**P**roduct）、目的（**P**urpose）、標準（**S**tandards）一致？

每一個不一致都是一個候選 bug。啟發法讓探索 session 持續產出點子，而不會枯竭。

---

## 探索式測試的定位

它**補充**腳本式測試 —— 不取代它。

| 腳本式測試 | 探索式測試 |
| --- | --- |
| 可重複、可自動化 | 隨機應變、由人驅動 |
| 找*已知*的風險 | 找*未預期*的風險 |
| 擅長迴歸 | 擅長新／變動的區域 |

用腳本式測試當迴歸防護網；在風險*未知*之處用探索式 session —— 也就是敏捷測試象限（#M1）的第三象限。

## 工具演示

在 `/section-blackbox` 開啟**探索式測試探索器**：

1. 讀一份範例**章程** —— 注意它的任務形狀。
2. 走一遍 **SFDIPOT** 清單 —— 對產品的七個角度。
3. 瀏覽 **HICCUPPS** 啟發法，找下一個測試點子。
4. 用 session 計時器與觀察日誌維持紀律。

---

## 小結

- 探索式測試＝同時進行的**學習＋設計＋執行**，邊做邊調適。
- 它是**有紀律的、非無結構** —— 紀律是那份**章程**，不是腳本。
- **SFDIPOT** 是覆蓋模型；**HICCUPPS** 是啟發法工具箱。
- 它補充腳本式測試 —— 在風險未預期之處最有用。

**課堂練習：** 為一個你熟悉的功能寫一份章程。再為每個 SFDIPOT 字母列出一件要試的事。
