# 測試自動化金字塔
### 不是*哪些*層級 —— 而是每一層*各多少*

軟體測試視覺化系列 #17
搭配工具：`/section-types`（[PyramidAdjusterExplorer](../../src/components/PyramidAdjusterExplorer.js)）

<!-- #16 點名了層級；這一講談的是它們的「比例」。整堂課就是一個取捨：又快又便宜但狹窄的測試，對上又慢又貴但廣的測試。 -->

---

## 為什麼有這一講

- #16 說了單元、整合、端到端的存在。它沒說**各該有多少**。
- 比例錯了的測試套件，又慢、又脆、又貴 —— 即使每個測試都通過。
- Mike Cohn 的*測試自動化金字塔*，就是讓套件維持可負擔的形狀。
- 這一講談的是一個取捨，用三種方式來看。

---

## 取捨 —— 一個測試一個測試地看

當你沿層級*往上*移，每一個測試都會變得：

| | 單元 | 整合 | 端到端 |
| --- | --- | --- | --- |
| 速度 | 快（毫秒） | 中等 | 慢（數秒以上） |
| 維護成本 | 便宜 | 中等 | 昂貴 |
| 每個測試的真實度／信心 | 狹窄 | 中等 | 廣 |

沒有哪一層「最好」 —— 每一層都用速度與成本去換真實度。

---

## 金字塔的形狀

健康的比例：**大量快測試、少量慢測試。**

```
        /\        端到端     ~10%   慢、廣
       /  \
      /    \      整合       ~20%
     /      \
    /        \    單元       ~70%   快、窄
   /__________\
```

寬廣的單元底座給你快速回饋；窄小的端到端尖端給你端到端的信心。這個形狀是一個*控制成本*的裝置。

---

## 反模式一：冰淇淋甜筒

把金字塔倒過來 —— 大多是端到端測試、幾乎沒有單元測試：

```
   \__________/   端到端     ~70%
    \        /
     \      /     整合       ~20%
      \    /
       \  /       單元       ~10%
        \/
```

- 套件很**慢** —— 每次執行都得等整個系統。
- 它很**脆（flaky）** —— 端到端測試會因不相關的原因失敗。
- 失敗無法定位 —— 到底是*哪個*單元壞了？

---

## 反模式二：沙漏

單元與端到端測試都不少 —— 但**整合**這個中段被餓著：

```
   \________/    端到端      ~50%
    \      /
       ||         整合       ~10%   ← 缺口
    /      \
   /________\    單元        ~40%
```

單元都通過、系統端到端也通過 —— 但**模組之間的接縫**（#16 講的整合缺陷）沒被測。缺陷正好藏在那塊缺掉的中段。

---

## 三個衍生屬性

從任一組 單元／整合／端到端 比例，可推出三個特質：

- **執行速度** —— 單元為主時高，端到端為主時低。
- **維護成本** —— 端到端為主時高（測試易碎），單元為主時低。
- **信心程度** —— 在平衡的金字塔附近達到最高；*兩個*極端都會拉低它（甜筒又慢又脆；全單元的套件則從未測過整體）。

你是在一個三方取捨裡選一個點，而不是把某一個數字最大化。

---

## 工具演示

在 `/section-types` 開啟**金字塔調整器**：

1. 從 **Ideal** 預設（70 / 20 / 10）開始 —— 注意速度與信心都高。
2. 切到**冰淇淋甜筒**（10 / 20 / 70）—— 看著速度與維護成本變糟。
3. 切到**沙漏**（40 / 10 / 50）—— 信心下降，儘管單元百分比看起來沒問題。
4. 自己拖動比例，找出信心達到最高的位置。

---

## 一個現代的但書

- 確切的 70/20/10 是一個經驗法則，不是定律。
- 快速的記憶體內整合測試，讓部分團隊改採「測試獎盃」—— 一個更胖的整合中段。
- 但有一條規則在每一種變體中都成立：**一個測試越慢、越廣，你就該越少依賴它。**

## 小結

- 金字塔談的是**比例**，不是有哪些層級。
- 往上：更慢、更貴、更廣。往下：更快、更便宜、更窄。
- **冰淇淋甜筒**＝又慢又脆；**沙漏**＝接縫沒測。
- 速度、維護、信心是三方取捨 —— 朝平衡的形狀走。

**課堂練習：** 估算你真實套件的 單元／整合／端到端 比例。它是哪一種形狀？最便宜能加的一個測試是什麼，能把它推向金字塔？
