## 回歸測試問題

每次程式碼編輯後，最安全的做法是重新執行整個測試套件。

**但這在實務上代價高昂：**
- 大型系統有數千個測試，完整執行可能需要數小時。
- CI 流水線被測試時間拖慢，影響每位開發者的回饋速度。
- 大多數測試與任何特定的變更完全無關。

**回歸測試選擇（RTS，Regression Test Selection）** 問的是：針對某個特定編輯，測試套件中哪個子集是*必要*重新執行的？

如果一個編輯**不可能改變**某個測試的結果，就可以安全地略過它。挑戰在於如何——廉價且正確地——做出這個判斷。

<!-- 成本問題有充分的文獻記載。Google（Memon 等人，2017）報告指出，在規模化環境中對每次提交重新執行所有測試是不可行的，因此採用了選擇與優先化策略。RTS 的學術文獻可追溯至 Rothermel 與 Harrold（1994、1996），至今仍是活躍的研究領域。核心張力在於精確度（只重新執行真正受影響的測試）與安全性（絕不略過可能因編輯而失敗的測試）之間。 -->

---

## 安全性需求

**定義：** 若一個 RTS 技術從不遺漏任何結果可能因編輯而改變的測試，則稱它是*安全的*。

正式地說：設 `E` 為一個編輯，`T_i` 為一個測試。若在修改後的程式對 `T_i` 的輸入執行時，存在任何一種執行結果與原始程式不同，則 `T_i` 必須包含在選擇集合中。

**為什麼安全性很重要：** 不安全的技術可能在編輯引入回歸問題時給出綠色訊號——原本能夠攔截問題的測試被略過了。

大多數實務的 RTS 技術是*保守的*——它們可能包含結果實際上未受影響的測試（假陽性），但絕不會遺漏真正受影響的測試。

<!-- 安全性的正式定義來自 Rothermel 與 Harrold（1996）。不安全的技術可能造成虛假的信心——CI 流水線通過，但回歸問題已悄悄地被引入。在實務中，每個團隊都必須決定其風險容忍度；保守的過選擇是常見做法。 -->

## 影響集合 —— 編輯的前向切片

編輯陳述式 `s` 後，哪些其他陳述式可能受到影響？

陳述式 `s` 的**前向切片**（記為 `FS(s)`）：
> 所有編輯 `s` 可能*到達*的陳述式集合，透過資料相依（`s` 定義的值被下游使用）與控制相依（`s` 處的分支控制下游陳述式是否執行）。

`FS(s)` 就是**影響集合**——編輯 `s` 可能影響其行為的精確陳述式集合。

**核心洞見：** 一個測試因該編輯而可能受影響，若且唯若它執行過 `FS(s)` 中的至少一個陳述式。

<!-- 前向切片是第 58 講中介紹的向後切片的鏡像。向後切片回答「什麼影響了這個輸出？」；前向切片回答「這個陳述式可能影響什麼？」兩者都是程式相依圖中的可達性閉包，但方向相反。在 RTS 中，我們需要正向方向。 -->

---

## 靜態選擇 —— 保守、永遠安全

**演算法：**

1. 計算已變更陳述式 `s` 的前向切片（影響集合）`FS(s)`。
2. 對每個測試 `T_i`，檢查它執行的陳述式集合（其動態軌跡）。
3. **選擇 `T_i`**，若且唯若其軌跡與 `FS(s)` 有交集。

這是*靜態*的，因為影響集合只需根據程式結構計算一次，然後與每個測試的已記錄軌跡比較。

**安全性保證：** 如果 `s` 處的編輯可能影響 `T_i`，則 `T_i` 執行過 `FS(s)` 中的某個陳述式，因此 `T_i` 必定會被選中。

**取捨：** 任何恰好執行了 `FS(s)` 中某個陳述式的測試都會被選中，即使在那個特定輸入上，變更的值實際上並未流向該測試的輸出。

<!-- 靜態選擇（將軌跡與前向切片匹配）對應於 Rothermel 與 Harrold 的安全靜態 RTS。軌跡必須從先前的執行中保存——這是現代 CI 系統自動維護的「測試歷史」或「覆蓋率設定檔」。Pytest-testmon 和 Jest 的 --changedSince 等工具實作了此想法的變體。 -->

---

## 動態選擇 —— 精確、仍然安全

靜態選擇在測試*執行過* `FS(s)` 中某個陳述式時選擇該測試。
但執行 `FS(s)` 中的陳述式並不意味著在那次執行中，編輯的值確實*到達*了測試的輸出。

**動態選擇使用動態向後切片：**
- 測試 `T_i` 受影響，若且唯若已變更陳述式 `s` 在 `T_i` 輸出準則的**動態向後切片**中。
- 動態切片只包含值或控制決策確實在那次特定執行中流向輸出的陳述式——而非任何在理論上可能如此的陳述式。

**結果：** 動態選擇是靜態選擇的嚴格子集。

$$\text{動態受影響} \subseteq \text{靜態受影響}$$

動態選擇更精確（重新執行的測試更少），但成本更高（需要對每條軌跡計算動態切片）。

<!-- 動態選擇由 Agrawal 等人（1993）研究，後來在程式相依圖的框架下被正式化。動態向後切片的計算方式與第 59 講（缺陷定位與切丁）相同：回放軌跡、追蹤活躍資料相依邊，並在限縮到那些活躍邊的 PDG 上做閉包運算。 -->

## 實作範例 —— `classify`

```javascript
function classify(n) {
  let label = "zero";       // s2
  let sign = 0;             // s3  ← 在此編輯
  if (n > 0) {              // s4
    label = "positive";     // s5
    sign = 1;               // s6
  } else if (n < 0) {       // s7
    label = "negative";     // s8
    sign = -1;              // s9
  }
  return label;             // s11
}
```

輸出準則：`s11` 處的 `label`。
**編輯：** 變更陳述式 `s3`（`sign = 0`）。

軌跡：`pos`（n=5）、`neg`（n=−3）、`zero`（n=0）。

<!-- classify 函式在第 58 講引入，並在第 59、60 講中使用。此處用於 RTS：編輯位於 s3（sign = 0），輸出為 s11 處的 label。sign 變數沒有通往 label 的資料或控制路徑，這將使動態結果更具教學意義。 -->

---

## 實作範例 —— 靜態選擇

**影響集合**（`s3` 的前向切片）：僅 `{s3}`。
`sign` 從未被用於任何到達 `label` 的計算，也不控制任何超出其現有範圍的分支——`s3` 在前向方向上沒有後繼者。

每條軌跡都執行了 `s3`（它出現在每個輸入的執行路徑上），因此每條軌跡的步驟都與 `{s3}` 有交集。

| 軌跡 | 執行 s3？ | 靜態判定 |
|---|---|---|
| `pos`（n=5） | 是 | **重新執行** |
| `neg`（n=−3） | 是 | **重新執行** |
| `zero`（n=0） | 是 | **重新執行** |

**靜態：重新執行全部 3 / 3 個測試（0 個可安全略過）。**

<!-- s3 定義了 `sign`，但在 classify 的 PDG 中，sign 沒有資料相依後繼者——它被定義（s3、s6、s9）但從未被用於任何到達輸出的計算。因此 s3 在 classify PDG 上的前向切片只有 {s3} 本身——沒有後繼者。然而每條軌跡都執行了 s3，所以靜態選擇必須保守地選擇所有三條軌跡。 -->

---

## 實作範例 —— 動態選擇

對每條軌跡，計算 `s11` 處 `label` 的**動態向後切片**。
若 `s3` 出現在某條軌跡的動態向後切片中，則該軌跡受影響。

| 軌跡 | label@s11 的動態向後切片 | 包含 s3？ | 動態判定 |
|---|---|---|---|
| `pos` | s4, s5, s11 | 否 | **可安全略過** |
| `neg` | s4, s7, s8, s11 | 否 | **可安全略過** |
| `zero` | s2, s11 | 否 | **可安全略過** |

**動態：重新執行 0 / 3 個測試（全部 3 個可安全略過）。**

`s3` 從未出現在任何軌跡的動態向後切片中，因為 `sign` 在任何執行中都從未流向 `label`——在 `s3` 定義的值根本沒有被用於輸出的計算。

<!-- 這是與靜態選擇的關鍵對比：靜態被迫選擇所有軌跡，因為 s3 出現在每條軌跡的執行步驟中。動態則審視什麼值實際上流向了輸出，並正確識別出 sign 在任何輸入上都與 label 無關。結果：相較於靜態的 0 個可跳過，動態可跳過 3 個——對此次編輯減少了 100% 的測試執行量。這是一個靜態過選擇而動態精確的清晰教學案例。 -->

---

## 靜態 vs 動態 —— 摘要比較

| 屬性 | 靜態 | 動態 |
|---|---|---|
| 選擇準則 | 軌跡執行了 `FS(s)` 中的任何陳述式 | 已變更陳述式在軌跡的動態向後切片中 |
| 安全性 | 永遠安全（保守） | 永遠安全（精確） |
| 假陽性 | 可能——可能選擇未受影響的測試 | 無——只選擇真正受影響的測試 |
| `classify`（編輯 s3） | 3/3 重新執行 | 0/3 重新執行 |
| 成本 | 低——只需一次前向切片計算 | 較高——需要對每條軌跡計算動態切片 |

動態受影響 ⊆ 靜態受影響 ⊆ 所有測試。

<!-- 這個層次關係在一般情況下是嚴格的：存在使動態受影響集合真包含於靜態受影響集合的編輯與程式。classify/sign 範例是一個極端案例（動態集合為空）。在實務中，當精確度至關重要且軌跡儲存可用時，使用動態 RTS；當選擇速度優先時，使用靜態 RTS。 -->

## 工具演示

在 `/section-slicing` 開啟**回歸**分頁（切片回歸探索器）：

1. 選取 `classify` 場景。
   - 左側顯示帶有當前輸出準則（`s11` 處的 `label`）的 PDG。
2. 點擊陳述式 `s3`（`sign = 0`）以標記為已變更的陳述式。
   - 前向切片影響集合 `{s3}` 被高亮顯示。
3. 切換至**靜態**模式——三條軌跡（`pos`、`neg`、`zero`）全部標記為受影響（紅色）。
4. 切換至**動態**模式——三條軌跡全部標記為安全（綠色）；每條軌跡的動態向後切片都不包含 `s3`。
5. 嘗試不同的編輯：點擊 `s2`（`label = "zero"`）——觀察靜態和動態現在都選擇所有軌跡（因為 `s2` 出現在每條軌跡的 `label` 動態向後切片中）。

## 小結

- 每次編輯後，**回歸測試選擇（RTS）** 識別必須重新執行的測試子集——那些結果可能因編輯而改變的測試。
- 一個技術是**安全的**，若它從不略過真正受影響的測試；保守技術可能過度選擇。
- 已變更陳述式的**前向切片**是影響集合——所有通過資料相依與控制相依從編輯可到達的陳述式。
- **靜態選擇：** 若測試的已記錄軌跡與影響集合有交集，則重新執行。永遠安全；可能過選擇。
- **動態選擇：** 只有在已變更陳述式出現在該測試對輸出的動態向後切片中時，才重新執行。精確；動態受影響 ⊆ 靜態受影響。
- 這完成了四種切片式測試技術：**程式切片**（#58）、**缺陷定位與切丁**（#59）、**切片覆蓋**（#60）、**回歸測試選擇**（#61）。

**課堂練習：** 對 `classify` 函式，找出一個靜態與動態選擇相同測試集合的編輯，以及一個動態嚴格選擇更少測試的編輯。
